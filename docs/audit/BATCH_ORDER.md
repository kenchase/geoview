# High-confidence colour migration: batch order

## Scope and execution boundary

This is a plan, not an implementation. Authority: [settled decisions](../COLOUR_DECISIONS.md) and [proposed mapping](../COLOUR_MAPPING.md). Counts were checked against current source rather than copied from the mapping's aggregate inventory.

Only these substitution types are considered:

1. **T1:** `theme.palette.geoViewColor.X` to the existing `theme.palette.X` role, where the current meaning already fits. Optional chaining and a redundant fallback to the same standard role are part of one substitution, not additional substitutions.
2. **T2:** exact theme-root literals `#515ba5` (case-insensitive) to `primary.main`, and `#393939` to `text.primary`.
3. **T3:** the two divider backgrounds using `palette.primary.contrastText` to `palette.divider`.
4. **T4:** status consumers of `geoViewColors.error|warning|info|success` to the matching palette role.

**Confirmed planning choice:** list non-equivalent High-confidence candidates as held, not executable. Do not change theme roots or generator wiring to make a candidate pass. T3 is the only approved appearance change. High confidence in a semantic role is not proof of equal resolved values.

Excluded from every batch: indexed ramp references, `transparent`, `unset`, shadows, map rendering, OpenLayers, drawing styles, fixtures, demos, vendored CSS, and all Low-confidence clusters. An out-of-scope expression beside a target remains unchanged. No palette API redesign, dependency upgrade, CSS-variable work, focus-contract redesign, or cleanup of unrelated overrides is included.

## Source findings that constrain the batches

- [The palette generator](../../../packages/geoview-core/src/ui/style/themeOptionsGenerator.ts) assigns `primary.main` directly from `geoViewColors.primary.main`: T1 primary-main substitutions are equal under all four GeoView themes.
- The same generator assigns `text.primary` from **`textColor.light[50]`**, not `textColor.main`. All **29 `textColor.main` consumers in 18 files** are held. This includes expressions already falling back to `palette.text.primary`: removing their first branch still changes GeoView output.
- [Custom legend](../../../packages/geoview-custom-legend/src/custom-legend-style.ts) contains the two T2 candidates. `#515BA5` matches the `geo.ca` primary root, not every theme's primary. `#393939` matches the default text root, not the generated `text.primary` shade. Both are held.
- The error/loading backgrounds use `lighten(0.7, 0.6)`, whereas palette status `light` uses `light[600]` without that alpha. These two T4 candidates are held. Keep the `.registered` state's grey background and `info.main` foreground unchanged: the mapping marks that state's intent Low confidence.
- The generator's **16 status-role seed assignments** already initialize the four standard slots. They are not 16 executable replacements: replacing their right-hand sides with the palette being initialized would be circular; indexed right-hand sides are also explicitly excluded.
- Reusable UI wrappers can receive an external MUI theme without `geoViewColor`. See [external-theme safety](../../programming/styling-best-practices.md#2--theme-tokens-and-external-theme-safety). Even an equal GeoView substitution may turn an omitted external-theme declaration into an explicit colour. The UI batches therefore require an external-theme parity check, not just GeoView screenshots. If output changes beyond T3, hold that substitution rather than inventing a new fallback or treating it as an approved visual change.
